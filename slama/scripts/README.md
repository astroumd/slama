# SLAMA Scripts

Utility scripts for inspecting, validating, and updating the SMA SMAX/Valkey
database and `conf/smax.json` configuration.  All scripts that require a live
database connect to `localhost:6380` by default (the SMA Valkey server).

Scripts that require the SLAMA package should be run with `uv run` from the
repo root.  Scripts that only need `redis-py` (`dump_redis.py`,
`dump_redis_py27.py`) can be run directly.

---

## dump_redis.py

Dump raw keys and values from the Valkey database.

```bash
# Print all keys in tree form
uv run scripts/dump_redis.py

# Print only true leaf paths (no intermediate branch nodes)
uv run scripts/dump_redis.py --flat

# Print leaves with their values
uv run scripts/dump_redis.py --flat --values

# Strip the top-level table wrapper (e.g. <SMA>) from key names
uv run scripts/dump_redis.py --flat --strip
```

The `--flat --strip` output is what feeds `compare_monitor_points.py`.  Without it,
intermediate branch paths (e.g. `antenna:1:if:1:scanspec`) appear alongside
their children; `--flat` filters those out so only true leaf variables remain.

### dump_redis_py27.py

Python 2.7-compatible version of `dump_redis.py` with identical options.
Use when the host system does not have Python 3 available.

## compare_monitor_points.py

Compare monitor points defined in `conf/smax.json` against the flat list of
variables actually present in the Valkey database.

The Valkey variable list is read from `docs/all_monitor_points.txt` by default
(generated by `dump_redis.py --flat`).

```bash
# Variables in Valkey that are missing from smax.json (default)
uv run scripts/compare_monitor_points.py --missing

# Variables in smax.json that are absent from Valkey (stale definitions)
uv run scripts/compare_monitor_points.py --in-smax

# Variables present in both
uv run scripts/compare_monitor_points.py --common

# Summary counts only (no names)
uv run scripts/compare_monitor_points.py --summary

# Collapse indexed variants (e.g. DSM:roach2-[01-08]:FOO into one line)
uv run scripts/compare_monitor_points.py --missing --compact

# Use non-default input files
uv run scripts/compare_monitor_points.py \
    --smax src/slama/conf/smax.json \
    --valkey docs/all_monitor_points.txt
```

The `--missing` output is the typical starting point for `smax_from_valkey.py`.

## smax_from_valkey.py

Query the live Valkey database for variables that are missing from `smax.json`
and generate the corresponding `smax.json` fragment.  Detects `__each__`
expansion groups and zero-padded index ranges automatically.

Input is a file of missing SMAX paths (one per line), typically saved from
`compare_monitor_points.py --missing`.

```bash
# Generate JSON fragment for missing variables (stdout)
uv run scripts/smax_from_valkey.py valkeynotsmax.txt

# Write to a file
uv run scripts/smax_from_valkey.py valkeynotsmax.txt --output missing_entries.json

# Merge the generated entries into conf/smax.json and write the result
uv run scripts/smax_from_valkey.py valkeynotsmax.txt \
    --merge --output smax_updated.json

# Merge into an explicit smax.json path
uv run scripts/smax_from_valkey.py valkeynotsmax.txt \
    --merge /path/to/smax.json --output merged.json

# Report how many variables could not be fetched, and list their names
uv run scripts/smax_from_valkey.py valkeynotsmax.txt --verbose

# Non-default host/port
uv run scripts/smax_from_valkey.py valkeynotsmax.txt \
    --host sma-valkey --port 6380
```

**Merge precedence:** when `--merge` is used, `smax.json` values always win on
conflicts.  This preserves validated descriptions, units, and thresholds while
adding new entries.  Variables whose `smax_pull` query fails are silently
omitted from the output and counted in the summary printed to stderr.

### Typical workflow

```bash
# 1. Dump all Valkey leaves
uv run scripts/dump_redis.py --flat > docs/all_monitor_points.txt

# 2. Find what is missing from smax.json
uv run scripts/compare_monitor_points.py --missing > valkeynotsmax.txt

# 3. Generate smax.json entries and merge
uv run scripts/smax_from_valkey.py valkeynotsmax.txt \
    --merge --output smax_updated.json --verbose

# 4. Review smax_updated.json, add descriptions/units, then replace conf/smax.json
```

## fakeobs.py

Simulate SMA observatory observations by writing fake antenna tracking,
weather, and Tsys data to SMAX.  Used for development and testing when the
real telescope hardware is unavailable.

```bash
# Run from src/slama/ (requires a live SMAX server)
cd src/slama
uv run fakeobs.py
```

Writes continuously until interrupted with Ctrl-C.

---

## simple_smax_check.py

Quick sanity check that SMAX read/write is working.  Writes a random float to
`weather:forecast:gfs:test_tau` and reads it back, printing the result.

```bash
python scripts/simple_smax_check.py
```

---

## printmonsys.py

Development/debug script that loads `conf/smax.json` into a `MonitorSystem`
tree and prints the hierarchy.  Not intended for production use.

---

## recursewithtreelib.py / treetest.py

Early prototypes for the `treelib`-based monitor system hierarchy.  Retained
for reference; superseded by `MonitorSystem` in `src/slama/monitor/`.

## Tests

Each main script has a corresponding test file:

| Test file | Covers |
|---|---|
| `test_dump_redis.py` | `filter_leaves()` in `dump_redis.py` |
| `test_compare_monitor_points.py` | `parse_range()`, `expand_smax()` |
| `test_smax_from_valkey.py` | `filter_input()`, `detect_each_group()`, `build_subtree()`, `deep_merge()`, and more |

Run all tests from the repo root:

```bash
uv run pytest
```
